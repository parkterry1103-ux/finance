# 주가해부실: 사건을 조사하고 판단의 변화를 기록하는 웹 서비스

## 해결하려 한 문제

경제 뉴스를 읽고 시장 움직임을 설명할 때, 사실과 추측을 섞거나 나중에 알게 된 정보를 당시 원인으로 받아들이기 쉽다. 정보를 더 많이 보여주는 것보다, 먼저 자신의 설명을 남긴 뒤 어떤 근거로 생각을 바꾸었는지 돌아볼 수 있는 흐름이 필요했다.

## 사용 흐름

1. 게시·검토된 사건을 선택한다. 현재는 Intel·SMCI·Netflix의 4개 시점 사례이며 최신 인텔은 2026년 11월 5일 미국 종가 기준이다. 7월 인텔 사례와 기록은 별도로 보존한다.
2. 동일 거래일의 기업·시장·업종 수익률과 발표 자료를 살펴본다.
3. 시장·산업·기업·복합·판단 보류 중 하나를 선택하고 이유를 기록한다.
4. 출처 시점, 다른 설명, 이미 반영된 기대와 반증 신호를 확인한다.
5. 최초 판단을 보존한 채 새 근거와 유지·수정 이유를 재검토로 추가한다.
6. 내 기록에서 검색·필터로 다시 찾고, 백업 파일을 다른 브라우저로 옮겨 이어서 본다.

화면에는 개발 단계, Rule ID, 제작 목적 같은 내부 설명을 노출하지 않는다. 사용자는 사건·근거·기록을 직접 다룬다.

## 핵심 구현 의사결정

### 기존 콘텐츠를 학습 사례로 재사용

`practice.ts`는 기존 Published summary에서 목록을 파생하고, 선택된 사건의 본문만 lazy import한다. 가격과 해설 숫자를 새 registry에 복제하지 않는다. 공개되지 않은 draft와 검토되지 않은 항목은 본문 loader에서 제외한다. 신규 데이터 공급자나 실시간 AI 호출을 추가하지 않았다.

### 시점과 인과관계의 경계

사건 기준일, 가격 기준일, 원고 발행일과 사용자가 기록한 시각을 구분한다. 출처의 발행일과 자료 기준일을 별도로 표시하고, 발행 시각이 없으면 추정하지 않는다. 기준일 뒤에 나온 자료는 당시 원인 근거에서 제외한다고 표시한다. 서로 다른 거래일의 benchmark는 비교에서 생략하며 수익률 차이를 원인 기여도나 예측 점수로 바꾸지 않는다.

### 최초 판단을 보존하는 데이터 모델

`PracticeJournal`은 version, 사건 ID, 가격 기준일, 최초 판단과 순서가 있는 재검토 배열로 구성한다. 재검토는 원본을 수정하지 않고 추가한다. 이유·확인 근거·다른 설명·반증 신호·파급효과 가설·질문 메모를 함께 저장한다. 사례당 50회, 입력당 3,000자 상한을 둔다.

### 개인정보와 저장 오류 처리

기록과 검색어는 브라우저 안에서 처리하고 analytics나 서버에 보내지 않는다. 저장 공간 부족·저장소 접근 차단·손상된 데이터는 빈 상태와 구분한다. 다른 탭의 변경은 storage event로 반영하고, 저장 전 이전 값을 비교해 오래된 상태의 덮어쓰기를 방지한다.

### 이동 가능한 백업

내 기록은 전체 JSON 또는 기존 단일 사건 JSON을 복원할 수 있다. 최대 16MB 파일을 검사하고 지원 사건·기준일·버전·분류·시각·문자 수·중복을 검증한 뒤 알려진 필드만 남긴다. 미리보기와 확인 전에는 저장하지 않는다. 기존 기록이 있으면 유지하며, 일부 저장에 실패하면 정확한 복원·유지·실패 수를 알린다. 불러오기 취소·완료 후에는 focus를 원래 버튼으로 돌려준다.

## 검증과 확인 방법

- `npm run validate:thinking-lab`: 기록 불변성, 순서, 시점, 저장 실패, 검색·정렬·필터, 백업 왕복과 잘못된 파일 fixture를 검사한다.
- `npm run validate:content`, `npm run check:types`, `npm run build:app`: 기존 콘텐츠 계약과 타입·번들을 검사한다.
- `scripts/thinking-practice-browser-qa.mjs`: Chromium의 1280/390/360/320/640px에서 기록·재접속·검색·필터·파일 다운로드·새 브라우저 복원·취소·중복 보존·손상·용량 실패를 검증한다.
- 자동화 결과와 화면 캡처는 `artifacts/thinking-practice/`에 생성한다. 테스트용 기록은 격리된 브라우저 context에만 넣으며 실제 사용자 저장소를 변경하지 않는다.

2026-11-06 로컬 검증에서 단위 검사 81개와 Chromium 브라우저 13개 검증 그룹이 통과했다. 다섯 viewport에서 가로 overflow와 console error는 0이며 기록 화면의 API 요청과 개인 메모 외부 전송도 0이다. 백업 미리보기·취소·복원·기존 단일 사례 호환·중복 보존·잘못된 파일·용량 초과 파일과 focus 복귀를 실제 브라우저에서 확인했다. 최신 인텔 상세의 숫자·카드 clipping과 broken image도 0이며 기존 글의 키보드 링크, 시장·산업·기업 분리, 새·옛 기록의 저장소 격리를 확인했다. 기사 route에는 기존 시장 가격 preload 1회가 유지되고, 새 기록 route의 API 요청은 0이다.

## 분석 범위의 명확화

핵심은 개별 기업의 주가 움직임을 시장 전체·산업 공통·기업 개별 요인으로 구분하고 근거를 비교하는 것이다. 리스크뿐 아니라 호재도 같은 틀로 다룬다. 시장이나 업종 대비 수익률 차이가 각 원인의 정확한 기여도는 아니며 주가 예측·투자 추천·계량적 리스크 분해 모델을 구현했다고 설명하지 않는다. 최신 인텔 자료는 AI 보조 출처 대조로 표시하고 소유자 직접 검토를 사칭하지 않는다. SOXX 분할 조정, 이미 공개된 실적과 당일 촉매 구분, 미확인 원인 표시가 이번 업데이트의 주요 데이터 품질 결정이다.

## 현재 범위와 한계

이 작업은 `codex/phase-6a-investment-thinking-lab`의 로컬 구현이다. 이번 변경의 commit·main 병합·Production 배포는 실행하지 않았다. 로그인, 서버 동기화, 실시간 과거 뉴스 탐색, 자유 날짜 차트와 자동 원인 판정은 구현하지 않았다. 브라우저 데이터 삭제 시 기록이 사라질 수 있어 백업 내보내기·복원을 제공한다. WebKit은 실행 환경 문제로 통과를 주장하지 않는다.

기존 개발 의존성 감사에서 취약점 4건이 발견됐고 production dependency 감사는 0건이었다. package·lock 파일을 바꾸지 않았으며, 외부 공개 전 의존성 갱신과 배포 검증은 별도 작업으로 남아 있다.
