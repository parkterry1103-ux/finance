01 · Purpose

이번 단계가 해결하려는 문제

진행 중

제품 질문

어떤 유입이 실제 읽기로 이어지고, 편집 콘텐츠가 기업·재무·가치평가·심층 리포트 탐색으로 연결되는지 현재는 확인할 수 없습니다.

운영 목표

페이지뷰와 의미 있는 행동을 분리하고, 원문 검색어·전체 URL·금액·가치평가 입력값·개인 식별자를 수집하지 않는 측정 계약을 만듭니다.

성공 기준은 이벤트 수 자체가 아니라 콘텐츠 읽기 완료와 다음 리서치 화면으로의 이동을 재현 가능한 방식으로 확인하는 것입니다.

08 · Risks

위험과 대응

공급자 제한

현재 확인된 제한: finance1은 Hobby 플랜입니다. Vercel Web Analytics의 기본 익명 페이지뷰는 활성화했지만 공식 커스텀 이벤트 수집은 Pro·Enterprise 기능입니다. 승인 없는 결제·플랜 변경은 하지 않으며, 실제 21개 이벤트 Production 전송이 확인되지 않으면 이 문서는 Completed로 표시하지 않습니다.

현재 대응

페이지뷰는 Production 공급자로 전송하고, 21개 행동 이벤트는 동일 typed 계약과 테스트 adapter로 완성합니다. 공급자 능력이 없을 때 UI를 막거나 이벤트를 다른 서비스로 우회하지 않습니다.

완전한 완료 조건

유료 기능 사용 승인이 별도로 주어지고 custom event 네트워크·dashboard 반영이 확인되거나, 사용자 승인을 받은 동등한 개인정보 보호형 공급자가 확정돼야 합니다.

추가 위험과 대응 보기
  • SPA 중복: route template과 page lifecycle key로 한 번만 기록
  • 민감 정보: allowlist payload와 validator로 원문 query·referrer·금융값 차단
  • 긴 글 오탐: 90% 도달과 최소 10초를 모두 만족할 때 완료
  • 공급자 장애: 모든 호출을 비동기·실패 격리해 UI와 이동을 보호
  • 번들 증가: 외부 dependency 없이 작은 공통 모듈로 구현
