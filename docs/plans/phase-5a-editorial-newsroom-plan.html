01 · Purpose

단계명과 프로젝트 목표

완료

사이트 재개편 5A — 편집 콘텐츠 레지스트리와 뉴스룸형 홈페이지. 하나의 자연어 원고를 홈페이지 요약, 전체 상세, 관련 기업, 상호 연결 콘텐츠와 향후 기업 리포트의 작성 시점 이슈에 재사용할 수 있게 합니다.

제품 문장: “오늘 주가가 움직인 이유와 다음에 확인할 것을 해부합니다.” 보조 문장: “뉴스를 기업의 사업·재무·가치평가로 연결합니다.”

02 · Problem

사이트에서 해결하려는 문제

완료
진입점이 데이터베이스 중심

현재 홈은 기업 분석과 거시경제 두 카드로 끝나며, 사용자가 오늘 무엇을 읽어야 하는지 보여주지 못합니다.

원고의 재사용 구조 부재

3Reads와 주가 해부 원고를 홈·상세·기업 페이지에 일관되게 연결하는 typed registry가 없습니다.

게시 안전 장치 부재

draft·verified·published·archived 상태, 출처·날짜·관계 검증을 하나의 규칙으로 강제해야 합니다.

사실과 해석의 경계

미확정 사건, 비교 기준, 상대수익률과 프리미엄 성격을 사용자에게 명확히 구분해야 합니다.

03 · User Flow

핵심 사용자 흐름

완료
  1. 자연어 원고와 출처를 전달받습니다.
  2. 사실·숫자·기준일을 검토하고 typed 콘텐츠로 변환합니다.
  3. 검증을 통과한 published 요약만 홈과 목록에 노출합니다.
  4. 상세에서 확인·미확인·출처·다음 확인을 읽습니다.
  5. 지원 기업과 관련 콘텐츠로 이동해 장기 맥락을 확인합니다.

06 · Data Model

데이터 구조와 노출 규칙

완료
ThreeReadsEdition

정확히 세 read, 공통 질문, 공통 맥락, 투자자 질문, 한 줄 정리, 출처와 관련 콘텐츠를 저장합니다.

draft | verified | published | archived
DailyStockDissection

주가 기준일, 직접 계기, 확인·미확인, 움직임의 성격, 비교 수치, 시장·기업 요인과 다음 확인을 저장합니다.

relative return = company return − benchmark return (%p)

홈에는 published 최신 요약만 정적으로 포함하고, 긴 본문은 상세 route에서 회사별 리포트와 같은 방식으로 lazy load합니다. draft·verified·미래 날짜·출처 누락 콘텐츠는 공개 index에서 제외합니다.

10 · Risk

위험 요소와 대응

대응 완료
게시할 실제 원고가 없음

PayPal·ASML 예시는 draft fixture로만 저장하고 Production은 검증 가능한 빈 상태를 사용합니다.

홈 bundle 팽창

summary index와 상세 lazy module을 분리하고 entry·Companies·insights 청크를 기준 build와 비교합니다.

미확정 사건 과장

확인·미확인을 분리하고 출처·상태가 없으면 published를 validator가 거부합니다.

기존 제품 회귀

기업 대시보드와 4B·4C 리포트는 구조를 바꾸지 않고 선택적 관련 콘텐츠 영역만 추가합니다.

12 · Plan vs Actual

계획 대비 실제 변경 사항과 검증 결과

완료 기록
계획대로 구현된 항목

두 typed 모델, 상태 selector, 상세 lazy registry, 홈·목록·두 상세 route, 기존 8개 기업 검색, 선택적 기업 연결과 editorial validator를 구현했습니다.

계획에서 변경된 항목

실제 published 원고를 만들지 않고 summary index를 0건으로 유지했습니다. 제공된 예시에는 원문 URL과 기준일이 없어 공개 안전 기준을 만족하지 않기 때문입니다.

추가·보류·제외 항목

두 브라우저 엔진을 같은 7개 viewport·9개 route로 검사하는 QA 스크립트를 추가했습니다. PayPal·ASML·커넥티드카 예시는 출처와 기준일이 없어 공개하지 않았고, 제외 범위의 DB·API·Function·외부 호출은 추가하지 않았습니다.

검증·Production 결과

Release Gate 22개, 운영 Chromium·WebKit 140개, 실제 Safari, canonical 검색·빈 상태·draft 비공개 경계, read-only smoke 59개 항목을 모두 통과했습니다. 초기 Safari QA에서 발견한 Hero 제목 명암 문제는 명시적 글자색을 적용해 재검증했습니다.
