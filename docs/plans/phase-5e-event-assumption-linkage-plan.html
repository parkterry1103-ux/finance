01 · Purpose

이번 단계가 해결할 문제

진행 중

사용자 질문

사건이 왜 중요하고, 어떤 사업 동인과 재무 숫자를 거쳐 어느 가치평가 가정을 다시 보게 했는지 한 흐름에서 확인합니다.

운영 원칙

편집물 게시나 가격 변동만으로 DCF·Reverse DCF·Company Brief·투자 논지를 자동 변경하지 않습니다. 검토와 실제 변경 기록을 분리합니다.

공개 화면은 매수·매도 신호가 아니라 근거, 불확실성, 검토 단계, 실제 결정과 다음 확인 항목을 설명합니다.

02 · Phase 5D

이전 단계 완료 상태

완료

NVIDIA·Meta의 시장가격, 모형 가치 범위, Reverse DCF, 내재 기대 후보와 민감도 UX가 Production에 있습니다. 나머지 6개 기업은 검증 모형이 없어 unavailable 상태를 유지합니다. Phase 5E는 기존 모형을 재계산하지 않고 그 위에 시점형 검토 기록을 연결합니다.

구현 예정

핵심 registry

사건, confirmed/unresolved, source IDs, business-driver impacts, financial metric links, valuation assumption links, review stage/status, decision record와 watch items를 typed registry로 관리합니다.

변경 기록

실제 가정 변경은 별도 ValuationAssumptionChange로 남기며 before/after 값·단위·모형 버전·작성자·시각이 모두 있어야 합니다. 이번 Production 값은 0건입니다.

06 · Screen Structure

기존 화면에 조건부 연결

구현 예정

Company Brief

해당 기업 레코드가 있을 때만 최근 영향 최대 3건을 보여줍니다. 사건·사업 동인·검토 단계를 짧게 요약합니다.

Financial Pivot

영향 레코드가 연결된 지표 행에만 근거·방향·검토 링크를 표시합니다. 수치 자체는 변경하지 않습니다.

Valuation

NVIDIA·Meta에 가정 검토 기록을 표시하고 실제 변경이 없으면 ‘기준 가정 유지’를 명확히 보여줍니다.

현재 Published 편집물에 회사 연결이 없으므로 편집 상세 impact 영역은 렌더링되지 않습니다. 고아 링크나 빈 섹션은 만들지 않습니다.

07 · Data & Performance

출처·버전·동적 로딩

계획

기준 entry는 766.48 kB raw / 208.02 kB gzip입니다. 기존 Release Gate 825 kB raw / 225 kB gzip 예산을 유지합니다.

09 · Test & Definition of Done

검증 계획

대기

정적·단위

타입, ID 중복, source·metric·assumption 참조, 상태 전이, 변경 기록 완전성, 0/NaN/Infinity 보호와 자동 변경 금지를 검증합니다.

브라우저

Chromium·WebKit·Safari와 1440·1280·1024·768·390·360·320px에서 overflow, heading, focus, 긴 한국어와 빈 상태를 확인합니다.

배포

typecheck, build, audit, 기존 validation, event impact validation, Release Gate, 12 Functions와 Production smoke를 통과한 뒤 완료 처리합니다.

위험과 대응
  • 인과 과장: 연결을 검토 대상과 confidence로 표현하고 주가 방향을 사업 인과로 자동 번역하지 않습니다.
  • 기준일 혼합: 사건일·검토일·모형 버전을 각각 표시합니다.
  • 가짜 변경 기록: 동일 버전 no-change만 허용하고 실제 변경 fixture를 Production에 두지 않습니다.
  • 번들 중복: 회사별 dynamic import와 조건부 UI로 제한합니다.
